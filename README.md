# AgenticDev — Agent 开发学习与求职仓库

> 目标：通过学习 Agent 开发，转行做 Agent 开发相关工作。
>
> 本仓库是**证据链**，不是存档。它最终要能回答一个问题：
> **「你能证明自己会做 Agent 开发吗？」**

---

## 为什么是这个结构

面试官不会问你"学过什么"，而是问"你做过什么、怎么做的、结果如何"。
所以这里的每一类产出都服务于三个目的：

1. **学懂**（笔记、源码阅读、踩坑记录）
2. **做到**（代码、项目、实验评测）
3. **证明**（作品集、博客、简历、面试故事）

## 目录导航

| 目录 | 作用 | 关键文件 |
|------|------|----------|
| `plan/` | 学习计划与进度台账 | `roadmap.md`、`progress.md`、`skills-matrix.md` |
| `notes/` | 知识库（你自己的话写的笔记） | `concepts/`、`comparisons/`、`source-reading/`、`pitfalls.md` |

| `portfolio/` | 作品集（别人 5 分钟能看懂） | `demos/`、`diagrams/` |
| `career/` | 求职物料 | `resume.md`、`project-stories.md`、`interview-qa.md`、`target-jobs.md` |
| `publishing/` | 公开输出（建立外部信号） | `blog/`、`talks/` |
| `resources/` | 资源与环境 | `learning-resources.md`、`environment.md` |

## 使用约定

- **进度日志要随手记**：每次学习/开发后花 2 分钟在 `plan/progress.md` 追加一条，别攒着补。
- **笔记用自己的话写**：收藏 ≠ 学会。每个概念笔记末尾加一句"我怎么理解它 / 它和什么像"。
- **踩坑是金矿**：任何"卡了很久才解决"的问题，立刻记进 `notes/pitfalls.md`，写清现象、原因、解法。
- **项目要有 README 和量化结果**：每个项目写清「业务问题 → 我的方案 → 量化结果」。
- **量化优先**：评测、实验、成本、延迟都要有数字，数字比形容词有说服力。

## 快速开始

1. 从 `plan/roadmap.md` 确定当前阶段。
2. 每次行动后更新 `plan/progress.md`。
3. 新技能点亮时更新 `plan/skills-matrix.md`。
